v1.6.1-fix: UI/UX round 1

Four real bugs surfaced during the v1.6.1 emulator drive and the
v1.6.1 unit test pass. Each is a follow-up to the LLM-drop:

Bug 1: CalendarGate.buildEventData returned null when dueAt was null
  (parseDueAt(null) -> null -> elvis -> return null). v1.6.1 has
  no LLM so dueAt is always null; the user's explicit "Add to
  calendar" tap was silently dropped. Fix: fall back to "now"
  when dueAt is null/blank/unparseable, so the event still fires
  with a sensible default time (user can adjust in the calendar
  pick UI). Still return null when a parseable dueAt is in the
  past -- that case should never create a "1-hour event for last
  Tuesday".
  Test: updated CalendarGateTest contract (2 tests rewritten to
  assert the new "fall back to now" behaviour; 1 test for past
  dueAt retained).

Bug 2: DecayViewModel "Quiet a while" showed "haven't touched in
  -1 days" for any person the user just added. Root cause:
  lastInteractionAt == null -> daysQuiet = Long.MAX_VALUE, and
  the UI's String.format("%d", Long.MAX_VALUE.toInt()) renders
  -1 (Int overflow). Fix: filter the Quiet a while list to
  exclude never-touched people. The empty-state copy
  ("Everyone's been touched recently. Nice.") is the right
  surface for a brand-new person; "Quiet a while" is for
  forgotten ones. Added lastInteractionAt to DecayRow so the
  filter can see the value.

Bug 3: capture_needs_person_message said "Add a person first to
  attach this note to." -- but v1.6.1's onSaveRaw saves notes as
  free-floating (personId = null). The "attach this note to"
  promise was a lie. Fix: updated copy to "Add a person first,
  then save your first note." -- honest about what the flow
  does.

Bug 4 (test only): AccessibilityContentDescriptionTest still
  required a11y_confidence_{high,medium,low} -- strings that
  labeled the LLM confidence pill, which was removed in v1.6.1.
  None of the 3 strings are referenced from any composable.
  Fix: removed the 3 entries from the test's requiredNames
  list.

Also fixed pre-existing: MigrationUpgradeRegressionTest was
untracked on the v1.6.0.1 commit and never worked because
Robolectric can't load SQLCipher's native library. Marked
@Ignore with a comment pointing at Migration10To11Test (which
covers the same SQL on raw SQLite and passes).

Test results: 449/0/8 (was 449/3/7 before fixes; 0 failures now,
8 skipped = 1 newly-skipped MigrationUpgradeRegressionTest + 7
pre-existing).
