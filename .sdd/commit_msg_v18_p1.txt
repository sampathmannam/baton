v1.8.0 (PROD-READINESS-P1-#1..#6): close the 6 Phase 1 P1 polish items

Phase 1 is now complete (5/5 P0 + 6/6 P1). This commit closes
the 3 P1 items that turned out to be real work, and locks the
3 that turned out to be pre-existing closures via audit notes.

P1 #1 (hardcoded English strings): CLOSED-pre-existing.
- Tier A/B/C labels were a v1.4 concern. v1.7.4 uses proper
  English "Inner / Active / Periodic / Dormant" via
  [com.baton.app.data.person.TierCadence] constants. The
  UI surfaces the tier name directly; no letter-code
  re-mapping is needed.

P1 #2 (vault recovery sheet print-to-PDF): DONE.
- New [com.baton.app.ui.privacy.RecoveryPdfGenerator]
  uses [android.graphics.pdf.PdfDocument] to write a
  single-page A4 PDF in cacheDir/recovery/. 4 columns
  of 6 rows of 24 BIP-39 words, monospace font (so
  "sigh" / "high" don't look identical), header with
  generation date and a "do not write index numbers"
  warning (the order is the secret).
- New "Save as PDF" row in
  [com.baton.app.ui.privacy.RecoveryPhraseScreen] co-
  located with the existing "Copy to clipboard" row.
  Hands the file to the system share sheet via
  FileProvider.
- file_paths.xml: new cache-path "recovery" exposes
  the recovery/ sub-directory to FileProvider. The
  existing "captures" entry is unchanged.
- 1/1 unit test (input contract: empty phrase
  rejected). Full PDF render is a manual QA gate on a
  real device (Robolectric's PdfDocument shadow cannot
  render pages; the actual render path is device-only).

P1 #3 (capture widget empty state): CLOSED-pre-existing.
- v1.7.4's [com.baton.app.features.capture.BatonCaptureWidget]
  is a single Glance "Tap to capture" button; it never
  renders a list. The "empty state" concern was for a
  list-style widget that v1.7.4 does not have. The
  widget is always actionable.

P1 #4 (brief privacy gate): DONE.
- [com.baton.app.data.brief.BriefGenerator.build] now
  filters `is_sensitive = true` rows out of all three
  sections (needsYouToday, waitingOnOthers,
  carriedOver). Spec §13: sensitive rows live in the
  local SQLCipher mirror only and must never surface in
  the morning/evening brief. The sync-engine already
  filters them at the network layer; this is the UI-
  side backstop.
- 4/4 new tests in
  [com.baton.app.data.brief.BriefGeneratorPrivacyTest].
  Existing 5/5 tests in
  [BriefGeneratorDedupTest] still pass (no regression).

P1 #5 (worry box year cap on re-edit): CLOSED-pre-existing.
- The v1.7.2 (P0-A) year cap is display-only in
  [com.baton.app.ui.today.worry.WorryBoxSection] (lines
  119-130): the `daysQuiet > 365` branch swaps "in N
  days" for "in YEAR (DATE)" on EVERY render. A re-
  edit of the worry's reviewAtEpochDay produces a new
  row → new render → the cap is re-applied by the same
  display logic. No separate re-edit code path is
  needed.

P1 #6 (decay "Mark as recent" + UndoController): DONE.
- New [com.baton.app.ui.today.decay.DecayViewModel.markRecent]
  bumps a single person's `lastInteractionAt` to now
  and pushes a
  [com.baton.app.data.undo.UndoableAction.MarkPersonRecent]
  for the snackbar. The pre-touch values (which may
  be null for never-touched people) are captured in
  the UndoableAction.
- [com.baton.app.data.local.PersonDao.restoreLastInteraction]
  is the inverse of `touch`: restores both
  `lastInteractionAt` (nullable) and `updatedAt` in
  one UPDATE. The null branch handles the
  "I marked a never-touched person as recent by
  mistake; undo should put them back in the
  new / never-touched group" edge case.
- [com.baton.app.data.undo.UndoController.undoLast]
  handles the new MarkPersonRecent variant.
- New "Mark recent" TextButton in
  [com.baton.app.ui.today.decay.DecaySection] per
  row. Monospace label, sits next to the reach-out
  status pill without inflating the row's height
  past 88dp.
- 9/9 tests in
  [com.baton.app.ui.today.decay.DecayViewModelTest]
  (was 7; +2 new for markRecent + undo path).
