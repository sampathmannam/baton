v1.9.4 (Drive-verify polish #4): cards truly use the screen

The v1.9.2 -> v1.9.3 -> v1.9.4-pre-polish cycle flipped the
DecayRow right-side controls twice (vertical stack -> horizontal
siblings) chasing "UI should use the screen properly". The
v1.9.4-pre-polish version had horizontal siblings + maxLines
caps, but the cards were still ~250px tall with significant
vertical bloat around them. This v1.9.4 closes the remaining
gaps in one pass:

1. DecayRow: heightIn(min = 88.dp) -> 72.dp, inner vertical
   padding 12 -> 10.dp, Spacer 2 -> 1.dp. The 88dp floor was
   a v1.7.3 anti-collapse guard, but with the v1.9.2 maxLines
   caps the natural height is already ~70dp. 72dp keeps the
   touch target comfortable without padding empty space.

2. DecaySection Column: outer vertical padding 8 -> 4.dp,
   inter-element spacedBy 8 -> 6.dp. Five gaps in the section
   header / subtitle / chips / banner / rows chain = 10dp saved
   end-to-end.

3. Today's win card: inner padding (16.dp all) -> (16.dp H,
   12.dp V), outer vertical padding 8 -> 4.dp, internal
   spacedBy 4 -> 2.dp. Two text lines + 24dp vertical padding
   is now ~70dp tall (down from ~94dp).

4. TodayScreen LazyColumn: contentPadding vertical 8 -> 4.dp,
   spacedBy 8 -> 4.dp. 4dp of vertical contentPadding + 4dp
   of inter-item spacing gives the surface room to breathe
   without wasting 1/4 of the screen on gaps.

Result: 5 full DecayRow cards visible on the Today screen
(emulator drive-verify), up from 3 in v1.9.3 and 4 in the
v1.9.4-pre-polish pass. 8+ cards visible per scroll instead
of 3-4. The Mark recent + Quiet a while pill stay as
horizontal siblings (the v1.9.2 Column stack was the wrong
fix; maxLines caps were the right one).

Files: 3 source files, versionCode 35 -> 36.
