v1.8.0 (PROD-READINESS-P2-#2): close Phase 2 P0 #2 (sync conflict UI)

The pre-v1.8.0 build had a `sync_conflicts` table + DAO
(write-only — rows accumulated in the local DB and the
user could inspect via a debug screen later) but no UI.
This commit adds the merge UI surface:

  - Settings sheet: a "Sync conflicts · N to resolve" row,
    visible only when N > 0 (the v1.5.0 vault-mode build
    has no cloud sync, so the row is dormant in normal use).
  - SyncConflictListScreen: LazyColumn of conflicts, ordered
    newest-first by `detectedAt`, with table + row + reason
    + relative time on each row.
  - SyncConflictDiffScreen: side-by-side "Your local change"
    vs "Server already had" payload boxes (full text,
    monospace), with "Keep local" / "Keep server" buttons.
  - Routes.SYNC_CONFLICTS + Routes.SYNC_CONFLICT_DIFF
    (`sync/conflict/{id}` with NavType.LongType arg) wired
    into the MainActivity NavHost.

v1.8.0 trade-off: the vault-mode build has no cloud sync, so
the "Keep local" / "Keep server" buttons are placeholders.
A future cloud-sync build wires the buttons to:
  1. Write the chosen payload back to the source table
     (persons / instructions / captures).
  2. Delete the conflict row from `sync_conflicts`.
  3. Enqueue a sync so the server reconciles.

Until that build, tapping either button shows an
AlertDialog ("Cloud sync is not enabled in this build")
and pops back to the list. The button affordance + the
diff layout are the right shape for the pilot so the UI
work is done now and only the resolver + sync wire-up
remains for the cloud build.

Compose gotcha (resolved): delegated properties (`var x by
remember { mutableStateOf(...) }`) look like functions to
the type-checker when used with `x(value)` syntax. The
fix is `x = value` (assign, not call). The error was
`Unresolved reference 'showConfirm'` because the compiler
tried to resolve `showConfirm` as a function name
rather than the delegated-property setter.
