The single-officer build is a corner case of the multi-officer pilot.
A pilot deployment with multiple officers in one station needs
per-officer rows so:
  1. The capture sheet's "Add person" + "Capture note" attribution
     is per-officer (officer A's notes are A's, not B's).
  2. The role model gates write APIs (READONLY officers can browse
     but not write).
  3. The audit chain signs with the user's id, not the device's.

v1.8.0 local-only trade-off: the table starts with one row (the
device owner, role = SENIOR_OFFICER). A future Settings → Provisioning
tab lets the admin add officers (out of scope for v1.8.0).

KSP gotcha (resolved): the KSP "MissingType" error on AppDatabase
was a stale KSP cache, not a real missing type. The fix was a
clean rebuild — no code change. (Bisection: each individual
piece — entities list, version bump, abstract DAO method,
migration, Hilt provider, Application wiring — compiles fine
in isolation; the KSP cache held a stale graph that resolved
once cleared.)

BatonApplication.kt gotcha (resolved): the fully-qualified
`kotlinx.coroutines.GlobalScope.launch(Dispatchers.IO)` did not
resolve because `launch` is an extension function on
CoroutineScope and the import was missing. Added
`import kotlinx.coroutines.launch` (and Dispatchers, GlobalScope)
and the call now resolves cleanly.

Test-name gotcha (resolved): backtick test names cannot contain
`..` (Kotlin's source-name encoding treats it as illegal). The
test "Role.values contains exactly the four documented variants"
becomes "Role values contains exactly the four documented
variants" (single space, no dot).
