v1.6.0.1: LLM graceful fallback + Room FTS migration fix

The v1.5.7 -> v1.6.0 upgrade was a brick on real devices:
the migration wrote the FTS4 table with the wrong column
order and backticks around the tokenizer name, so Room's
post-migration validateMigration step crashed the app on
first launch with `Migration didn't properly handle:
instructions_fts(...)`. Fresh installs were fine (Room
generates the schema from the @Fts4 entity), so CI never
caught the regression.

The on-device LLM library (libllama.so) is also missing
from the v1.6.0 release APK (the build runs with
-x vendorLlamaCpp -x vendorWhisperCpp to keep NDK out of
CI). Tapping Extract on a v1.5.7 install with the v1.6.0
APK now shows "No instruction found. Try rephrasing." --
misleading, because the user's text was never even read.
The fix surfaces the real reason (build has no LLM
library) instead.

What changed:

1. Room FTS4 migration (AppDatabase.kt: MIGRATION_10_11):
   the CREATE VIRTUAL TABLE statement now uses
   alphabetical column order (capturedAt, personId, title,
   rawText) and the unquoted tokenizer (tokenize=porter)
   that matches what Room generates from the @Fts4 entity.
   The "Expected ... Found ..." diff Room reports in
   logcat pins down the exact mismatch.

2. LlamaBridge: isNativeAvailable is now `open val` so
   tests can override it; the class-load-time probe
   continues to catch UnsatisfiedLinkError and return
   false when the JNI library is missing.

3. LlamaError: new `ModelNotAvailable` variant so the
   Extractor's existing `catch (e: LlamaError)` block
   catches the JNI-missing case cleanly (no more raw
   `UnsatisfiedLinkError` propagation).

4. CaptureViewModel: now takes a LlamaBridge in its
   constructor; exposes `llmAvailable: StateFlow<Boolean>`
   that mirrors the probe; the `onExtract` short-circuit
   sets a clear "AI extraction isn't available in this
   build" error instead of the misleading rephrasing
   message. Defense-in-depth: the Composable also
   disables the Extract button and renders a dedicated
   LlmUnavailableCard.

5. CaptureSheet: new LlmUnavailableCard composable
   (surfaceVariant, no red, no shame) with a
   "Save as plain note" button so the user can still
   keep the note when the LLM is off. Card sits above
   the existing model-not-downloaded card because the
   LLM library is the harder constraint.

6. strings.xml: 4 new strings (card title, card body,
   "Save as plain note" button label, the inline error
   message that the VM sets when onExtract short-
   circuits).

7. Tests: 2 new VM tests in CaptureViewModelTest
   (short-circuit + StateFlow wiring) + a
   TestLlamaBridge sibling in V156QaTest so the existing
   QA scenarios don't accidentally short-circuit on
   `mockk(relaxed = true)`'s `false` default.

Test result: 490 / 0 failed / 7 skipped (was 479
+ 11 new = 490; previous run had 8 failures: 3
RecoveryPhraseHoldToRevealTest (rewrote to read
strings.xml directly instead of going through
ApplicationProvider, because `testOptions.unitTests
.isIncludeAndroidResources = true` breaks 270+ other
Robolectric tests by enabling the AndroidKeyStore
provider) and 5 V156QaTest (caused by the LLM short-
circuit firing on `mockk(relaxed = true)`'s `false`
default)).

On-device verified (ZD2232FCR5): capture sheet shows
the new "AI extraction off" card with the honest
"this build does not include the on-device LLM
library" copy. Save-as-plain still works. Migration
v10 -> v13 runs cleanly on a v1.5.7 install.
