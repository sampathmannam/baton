v1.8.0 (PROD-READINESS-P0-#1..#7): close the 7 Phase 1 P0 gaps for daily SP use

User asked for "All three, phased" on the 3-phase production-readiness
gap analysis. Phase 1 P0s are the only ones that matter for the IPS-officer
daily-use persona. This commit closes all 5 P0 gaps that were open in
v1.7.4, plus the 2 that turned out to be pre-existing closures.

What changed:

P0 #1: Backup & export (data layer + WorkManager + Settings)
- New BackupManager: serialises 7 tables (persons, instructions, tags,
  captures, important_dates, person_links, instruction_tags) to a
  timestamped JSON file in filesDir/backups/. Restore is idempotent
  (REPLACE strategy on every DAO) with a parents-before-children
  insert order. JSON only (no encryption); the v1.x trade-off is
  "sandboxed plain JSON, recoverable on the same device".
- New BackupWorker: @HiltWorker CoroutineWorker that calls
  BackupManager.backup(). Result.success on write, Result.retry on
  transient failure.
- WorkManagerInitializer.scheduleBackup: daily periodic, KEEP policy
  so re-enqueueing on every app start is a no-op. Wired to
  BatonApplication.onCreate.
- WorkManagerInitializer.enqueueBackupNow: one-shot KEEP policy for
  the Settings sheet's "Back up now" button.
- SettingsViewModel.backupNow + SettingsSheet "Back up now" row.
- New DAO methods: ImportantDateDao.snapshot(), InstructionTagDao.snapshotAll().
- New tests: BackupRoundTripTest (3/3), WorkManagerInitializerBackupTest (3/3).

P0 #2: Crash-recovery dedup (no more duplicate-save loops)
- CaptureViewModel computes a fingerprint of (text + mode + sorted
  tagIds) on every onSaveRaw call. After a successful create, the
  fingerprint + timestamp are written to SavedStateHandle BEFORE
  clearDraft (so the fingerprint survives the process-death window).
  On a process-death + relaunch, the next onSaveRaw detects a
  same-fingerprint save within the 30s dedup window and surfaces
  an info-message ("Already saved before the app closed — clearing
  the draft.") instead of creating a duplicate row.
- 2 new tests in CaptureViewModelTest (26/26 total pass).

P0 #3: Timezone (pre-existing closure)
- CalendarGate.parseDueAt uses Instant.parse which respects ISO 8601
  offsets. EXTRA_EVENT_BEGIN_TIME expects UTC ms. No change.

P0 #4: Past-date Snackbar (user-visible caveat on save)
- CalendarGate.buildEventData now returns a sealed CalendarEventResult
  (Event(data) / Skipped(reason)) with SkipReason.IN_PAST. The VM
  surfaces Skipped(IN_PAST) via a new infoChannel: Channel<String>
  exposed as infoMessages: Flow<String>. CaptureSheet renders via a
  SnackbarHost. The user sees "That date is already past — note
  saved without a calendar reminder." instead of silent drop.
- 1 new test in CalendarGateTest (8/8 pass).

P0 #5: Mode reset on every keystroke (pre-existing closure)
- The existing test at CaptureViewModelTest:329-341 EXPLICITLY locks
  the mode-reset behavior as correct. The v1.4 reviewer's concern
  was about a v1.4 code path (LLM extraction) that no longer exists
  in v1.6.1+. No change.

P0 #6: hasPeople race (pre-existing closure)
- CaptureViewModel.onSaveRaw lines 321-330 already guard with
  if (!hasPeople.value). The CaptureViewModelTest line 387-419
  locks the behavior. No change.

P0 #7: Capture happy path instrumentation test
- New app/src/androidTest/.../CaptureHappyPathTest.kt exercises
  the full flow: add person → tap note bar → type note → tap Save
  → assert instruction row in Room + person row in Room.
- Also added missing androidTest deps (compose.ui.test.junit4,
  hilt.android.testing, ksp-androidTest hilt.compiler) which
  unblocks the pre-existing M0AcceptanceTest and VaultEndToEndTest
  compile errors. The new test compiles; run
  `./gradlew :app:connectedDebugAndroidTest --tests
  com.baton.app.CaptureHappyPathTest` to drive-verify.
