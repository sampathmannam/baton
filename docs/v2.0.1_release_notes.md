## What changed

### New features

- **Settings → Privacy → Audit log.** The audit chain has
  been writing rows since v1.8.0 (see
  `AuditChainWriter`); v2.0.0 had no surface for the user
  to see them. The new screen lists recent events
  (table, kind, row, time, JSON payload preview) and
  runs `AuditChainVerifier.verify()` on demand. A
  "Chain intact" green check or a "Chain broken" red
  icon is the headline; the broken case shows the
  first broken link's index + table + row so the user
  can act (or escalate).
- **Settings → Import from.** The v1.x PlainExporter
  was one-way. v2.0.1 adds the inverse path: pick a
  CSV or JSON from SAF, the importer parses the file,
  detects format from the first non-whitespace
  character (`{` → JSON, else → CSV), and upserts
  every row. Re-importing the same file is idempotent
  (upsert by id). The result snackbar reports
  inserted + updated counts so the user knows the
  work was real.

### New tests

- `data/retention/RetentionWorkerTest.kt` (2 cases)
  pins the firing contract: old captures + important
  dates are hard-deleted; old audit chain rows have
  their JSON payload REDACTED (preserving the hash
  chain integrity); the recent rows survive; the
  worker writes a `RETENTION_RUN` audit event so a
  forensic reader can verify "yes, retention ran on
  schedule".
- `data/export/BackupManagerTest.kt` (2 cases) is the
  e2e backup → wipe → restore round-trip the PM
  rating called out. A future change to either side
  of the contract (a new field in `backup()` that
  `restore()` doesn't know about, or a new field in
  the on-disk JSON schema) now has a test catching it.
- `features/audit/AuditLogViewModelTest.kt` (3 cases)
  pins the in-app audit viewer: empty chain verifies
  as Intact, writer + verifier agree on a 3-row
  chain, and a bogus row in the chain surfaces as
  BrokenAt.
- `data/export/PlainImporterTest.kt` (3 cases) is the
  CSV/JSON import round-trip.

### Bug fixes

- **Hilt `MissingBinding` for `HttpClient`** (latent
  in v1.9.x): the in-app "Check for updates" feature
  would have crashed with a Hilt `MissingBinding` if
  a user tapped the row. `UpdateModule` now provides
  a real `HttpClient(OkHttp)`. v1.9.x users on the
  build can no longer hit this; v2.0.0 was the
  carrier.

### Documentation

- **`docs/threat-model.md`** rewritten for the v2.0
  local-only architecture. A4 (network eavesdropper)
  and A6 (cloud attacker) are now "vacuous by
  design" instead of "vacuous by vault-mode". A new
  A7 (Google Play Services for ML Kit OCR) is added;
  the user can disable OCR in Settings if A7 is in
  scope. A new §7 ("§8.2 — Third-party SDK surface")
  honestly documents ML Kit OCR, correcting the v1.x
  "no third-party AI" over-claim.
- **`README.md`** updated: new "What this is NOT"
  section documents what was removed in v2.0
  (multi-device, team, cloud auth, etc.). The Stack
  section no longer mentions Supabase. The Privacy
  posture section mentions ML Kit OCR.
- **`docs/RUNBOOK.md`** new. Recovery flows for
  "data is gone", "app crashes on launch", "I forgot
  my vault PIN", "I want to back up", "I want to
  migrate from v1.x", "verify the APK", and "wipe
  before donating the device". The "SQLCipher
  error recovery" path is documented as a v2.0.2+
  follow-up (the AppInitializer catches the
  lib-load failure but not the runtime open
  failure).
- **`docs/v2.0.0_release_notes.md`** exists from the
  v2.0.0 ship; this is the v2.0.1 follow-up.

## What's still on the list (deferred to v2.0.2+)

- **SQLCipher error-recovery UI.** A v2.0.2 build will
  ship a "Database corrupt — wipe and start fresh"
  prompt on first launch. The v2.0.1 workaround is in
  the runbook: uninstall + reinstall, then restore
  from backup.
- **Cryptographic vault mode.** v2.0.0 + v2.0.1
  vault is behavioural (UI filter on `vaultMode`
  column). A v2.x moves hidden rows to a second
  SQLCipher DB with a second passphrase.
- **Removing `fallbackToDestructiveMigrationFrom(2..7)`.**
  Requires writing 6 schema migrations (v2-v7) for
  which I don't have the historical schema. Pre-v8
  users upgrading to v2.0.0 + must back up first; the
  release notes call this out loudly.
- **About page (dedicated screen).** The version is
  in the existing Settings storage card. A dedicated
  About screen with build info, dependency list,
  and source repo link is a v2.0.2 follow-up.
