# Kaavalan note v2.1.1 — "Hierarchy + Kaavalan rename"

**Release date:** 2026-08-25
**versionCode:** 45 (unchanged from v2.1.0)
**Branch:** `polish/kaavalan-note-rename-clean` (cherry-picks the 8 hierarchy commits from `polish/kaavalan-note-rename-squashed`)
**Tests:** 108 test files; full suite status pending (`./gradlew test` not run as part of this build)

> v2.1.1 is two things stacked:
>
>  1. **Brand rename** — `com.baton.app` → `com.kaavalan.note`, `Baton*` identifiers → `Kaavalan*`. The v1.9.10 "Baton" name is fully gone. The launcher label is "Kaavalan note" (unchanged from v2.1.0's `app_name`); only the package + class identifiers were renamed.
>  2. **Hierarchy polish** — the v2.0 "people → instructions → mentions → roster → dispatch" mental model is wired end-to-end. `MentionAndTagParser` + `RosterBuilder` + `AudienceResolver` + `DispatchComposerSheet` were the schema-level pieces already in main; this build wires the UI on top.

## What changed

### Brand rename (v2.1.1)

- **Package:** `com.baton.app` → `com.kaavalan.note` (every file, every import, every `BuildConfig` field).
- **Class identifiers:** `BatonApplication` → `KaavalanApplication`, `BatonTheme` → `KaavalanNoteTheme`, `BatonCaptureWidget` → `KaavalanCaptureWidget`, `BatonTileService` → `KaavalanTileService`, `BatonExtraWidgets` → `KaavalanExtraWidgets`, `BatonQuickNoteWidget` → `KaavalanQuickNoteWidget`, `BatonAccent` → `KaavalanAccent`, `BatonPreferences` → `KaavalanPreferences`. All `Baton*` `R.string` keys swept; 0 remaining.
- **BuildConfig fields:** `BATON_GOOGLE_OAUTH_CLIENT_ID` → `KAAVALAN_NOTE_GOOGLE_OAUTH_CLIENT_ID` (and the corresponding REDIRECT_URI). The placeholder default kept the v2.1.0 behaviour for out-of-the-box builds.
- **App label (`R.string.app_name`):** unchanged at `Kaavalan note` (this was already renamed at v1.9.10; v2.1.1 only renames identifiers below the surface).

### Hierarchy work (v2.1.1.3 + v2.1.1.4)

- **`ContactSyncService`** (new) — Hilt-injected, asks for `READ_CONTACTS`, lists up to 50 device contacts, creates a `Person` on pick. Wired into `HomeViewModel` as `importContact(displayName, phone)`.
- **`ContactPickerSheet`** (new) — `ModalBottomSheet` shown from `HomeScreen`'s empty state with a secondary "Import from contacts" `OutlinedButton` under the primary "Add a person" button. The single FAB note bar remains the primary input per the project's "one next action" rule.
- **`MentionAndTagParser`** (new) — parses `@mention` and `#tag` syntax out of instruction body text. Used by `RosterBuilder` to resolve the audience.
- **`RosterBuilder`** (new) — given an `Instruction`, returns the `Roster` (list of people) that should receive it. Case-insensitive designation lookup (the v2.1.1 release fixes a bug where `@si` wouldn't match a stored "SI" designation).
- **`AudienceResolver`** (new) — resolves a Roster to a delivery plan (DeliveryService + DeliveryReceiptDao).
- **`DispatchComposerSheet`** + **`DispatchViewModel`** (new) — UI to pick audience, compose message, fire dispatch. The Pick-audience chip AND the Next button are gated on `state.rosterReady` so the user can't open the audience picker before the roster finishes loading (race fix).
- **`DeliveryService`** + **`DeliveryReceiptDao`** + **`DeliveryReceiptEntity`** (new) — persistence + write path for delivery receipts.
- **E.164 phone normalization** — `ContactSyncService` and `RosterBuilder` normalize phones via `TelephonyManager` for country code detection (replaces the earlier `Configuration.locales` approach which was wrong for users with non-default locale).
- **Schema-drift log + roster ready flag + viewmodel passthrough** — three crash-recovery items squashed into the v2.1.1.1 stack.

### Code-review fixes (folded into the 8 hierarchy commits)

- All 15 issues from the v2.1.1 round-3 code review (E.164 phone, throwable scope, schema-drift log, roster ready flag, viewmodel passthrough, etc.)
- HierarchyDispatchEndToEndTest — 6 Robolectric + in-memory Room tests covering the full capture → dispatch → receipt flow.
- SnackbarHost added to HomeScreen Scaffold.
- `HomeViewModelTest` updated to pass the `contactSyncService` mock.

## Risk

- The hierarchy work is **untested on a real device**. Build is green (`./gradlew assembleDebug` succeeds) but the contact-pick → roster → dispatch round-trip has not been verified end-to-end on hardware. Run a smoke pass on the connected phone before shipping.
- The v2.1.1.1 P1/P2 security hardening (CharArray, schema verify, PII redaction, BuildConfig cleanup, clipboard cleanup, PDF cleanup, network policy) and the v2.1.1 P0 Google OAuth + PKCE work is **on the `release/v2.1.1-security` branch** and is NOT included in this build. If shipping, the security branch must be merged first.
