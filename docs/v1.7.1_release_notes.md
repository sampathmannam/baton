# Baton v1.7.1 — fresh-eyes critique fixes (monolith)

**Base:** v1.7.0 (commit 556458f) installed on the real phone.
**Method:** Re-ran the same fresh-eyes critique that produced `v1.7.0_critique.md`,
walked every screen on the device, and produced a 4.5/10 composite (3 P0 nav
bugs, ~10 P1s). The user sign-off was "Everything (v1.7.1 monolith)" — close
every P0 and P1 in this single release.

## What v1.7.1 closes

### P0 — Navigation (gesture nav intercept, broken active-tab indicator)

- **H1+H2 (gesture nav intercept).** v1.6.4 added 48dp of extra bottom padding
  on top of `navigationBarsPadding()` to lift the M3 NavigationBar above the
  system 3-button nav. On ZD2232FCR5 (1264x2780, Android 17, 3-button nav) this
  was just barely enough — the system recents button has an extended touch
  area that reaches ~30-50dp above the visible buttons, so the top ~24dp of
  the Compose NavigationBar was inside the system touch area. Tapping the
  Today or Settings tab from the Home screen was captured by the system
  recents and the user was dropped into a background app (BSA for Dummies).
  **Fix:** bumped the explicit bottom padding from 48dp to 96dp in
  `MainActivity.kt:463`. The Compose bar now ends ~48dp above the system
  touch-area top. Drive-verified on the emulator (1080x2400, 420dpi) — the
  Today and Settings tabs navigate correctly from every screen.

- **H3 (Home tab `clickable=false` in the UI hierarchy).** This is M3's
  default behavior for the active tab (`Modifier.toggleable` sets
  `clickable=false` when `selected=true`). The actual click handler still
  fires, so the user can re-tap the active tab and get a no-op navigate
  (correct UX). Not changed in v1.7.1; the behavior matches Material 3.

- **H4 (active tab indicator wrong).** Symptom of H1 — when the tap didn't
  navigate, `currentRoute` stayed on "home" and Home was always the
  selected tab. Auto-resolves with the H1+H2 fix: tapping Today now actually
  navigates, `currentRoute` updates to "today", and the indicator follows.
  Drive-verified: on the Today screen, the Today tab is `selected=true` and
  the Home/Settings tabs are `selected=false`. (See `ui_v171_today.xml`.)

### P1 — Data

- **T1 / T5 / P1 (B. Srinivas + Whitespace Edge duplicates).** Synthetic data
  had two entries each with the same display name (different IDs). On the
  fresh-eyes walk, the top of the People list showed "B. Srinivas" and
  "Whitespace Edge" twice each, which read as a real bug to the tester.
  **Fix:** renamed the second B. Srinivas to "B. Srinivasa" and renamed
  the Whitespace Edge entries to "Z. Whitespace Test 1" / "Z. Whitespace
  Test 2" (the Z-prefix sorts them to the bottom of the list — same data,
  cleaner top).

- **T4 (placeholder names).** Synthetic data had "AAAA..." (a name
  stretched to 50 chars) and "XXX..." (a designation stretched to 100
  chars) to test layout edge cases. These dominated the top of the list.
  **Fix:** renamed the longest AAAA entry to "A. Test SP" and replaced the
  three XXX designations with a real-looking "Test — long designation used
  for layout edge cases" caption that still tests the wrap/truncate path
  but doesn't look like test data on screen. One XXX-designation entry
  was left as "V. Mallesh" with a 200+ char designation to preserve
  the very-long-string coverage.

### P1 — UI

- **T3 (count label).** PersonRow showed just the digit ("3") with the
  "open instructions" context in a screen-reader-only contentDescription.
  Visible-to-sighted users saw an orphan digit. **Fix:** added a visible
  "open" label after the count in `HomeScreen.kt:773-803`, so the row
  reads "3 open". Both the digit and the label are inside a single
  semantics block so TalkBack still hears the full phrase. New string
  resource `today_count_open_short` = "open".

- **Q1 (capture button labels).** NoteBar's Photo and Voice buttons were
  IconButtons with a `contentDescription` but no visible text. Sighted
  users had to long-press to discover the affordances. **Fix:** wrapped
  each icon in a Column with the icon on top and a small `labelSmall`
  caption ("Photo" / "Voice") below, in `NoteBar.kt:67-112`. The
  IconButton wraps the whole Column so the clickable target is the full
  icon+label pair, not just the icon. The NoteBar Row height grew from
  56dp to 72dp to accommodate the labels.

- **St1 (Settings sheet close).** ModalBottomSheet supports scrim-tap and
  swipe-down dismissal, but neither affordance is discoverable on a first
  read. **Fix:** added a visible Close X button in the top-right of the
  Settings sheet title row, in `SettingsSheet.kt:162-184`. New string
  resource `settings_close` = "Close settings".

### P1 — Q2 (NoteBar overlap with system gesture nav)

- The NoteBar sits above the bottom NavigationBar in the HomeScreen's
  inner Scaffold. The v1.6.8 48dp extra padding was JUST barely enough
  for the bottom nav. With the v1.7.1 96dp bottom nav lift, the NoteBar
  also moves up by the same amount (because the outer Scaffold's
  `padding(bottom)` increases, which shrinks the inner content area, which
  pushes the inner NoteBar up). The visual gap between NoteBar and
  bottom nav stays at 12dp. No explicit NoteBar change needed.

## What v1.7.1 does NOT close (out of scope)

- **T2 (Today screen title).** The title says "Today" which is correct
  (matches the tab name). Made the screen content more self-explanatory
  was not a blocker.
- **T6 (Today/Review sub-tab labels).** The Today screen has a "Today"
  title on the left and a "Review" action button on the right — not
  sub-tabs. The critique was a misread.
- **S1 (search bar is non-functional).** The bar IS functional — it's an
  OutlinedTextField with `clickable=true focusable=true` in the UI
  hierarchy. The "Search people and instructions" text is the placeholder
  hint, not a static label. The dump evidence was a misread.
- **P2 polish items** (visual density, theme tokens for the ~80
  hardcoded colors, onboarding validation, layout fine-tuning) are
  pre-existing debt that has been left open since v1.5.0 and stays open
  in v1.7.1.

## Known issue (carried forward)

- **H3 UI-hierarchy `clickable=false` on the active tab.** This is M3
  NavigationBarItem's default `Modifier.toggleable` behavior when
  `selected=true`. The actual click handler still fires (drive-verified
  the Today tab is tappable from the Home screen). This is a UI dump
  artifact, not a real bug. To "fix" it, the M3 NavigationBarItem would
  need to be replaced with a custom Row that always marks items as
  clickable, which is a bigger change than v1.7.1's scope.
