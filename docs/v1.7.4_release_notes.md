**Tag:** v1.7.4 on branch `m0/skeleton-v1.7.0`
**versionCode:** 30 (was 29)
**versionName:** "1.7.4" (was "1.7.3")

**Source-of-truth:** `ui_v174_search.png`, `ui_v174_home.png` (emulator-5554, 1080x2400, 420dpi)

## Background

The v1.7.3 fresh-eyes critique (composite 7.5/10) closed 1 P0 + 4 P1 + 2 P2.
The People search/list screen had three latent UI bugs that the critique
called out under "looks fine on the seeded fixture, breaks on a long
station name or a stress-test row" — all three are user-visible
contract defects on a list item, not a polish issue.

Repro from the v1.7.3 APK on a 1080x2400 viewport:

1. **Word breaks inside hyphenated words.** Search result for a person
   with the long station "Station-with-a-very-long-name-that-might-
   wrap-on-mobile-screens" rendered "...wrap-on-mo / bile-screens"
   (the word `mobile` broken at `mo|bile`). Compose `Text` with
   `softWrap = true` and no `maxLines` will break any character
   position when the word doesn't fit the remaining line width.
2. **Truncation without ellipsis.** The "B. Srinivas" row showed
   "Sub-Inspector (Traffic) • District Traffic Wing, Waran" — the
   `Warangal` was clipped at the right edge of the screen with no
   `...` indicator, so the user can't tell whether the station is
   truncated or fully shown.
3. **Last row clipped behind the Quick note bar.** A second
   "B. Srinivas" entry was half-hidden behind the NoteBar because
   the LazyColumn `contentPadding(bottom = 88.dp)` cleared the FAB
   (56dp + 16dp + 16dp) but not the NoteBar (12 + 72 + 12 = 96dp).

The fixture data was fine; the test data (X's, AAAA's, the
`Station-with-a-very-long-name...` placeholder) made the bugs visible.
But the same bugs would fire on any real long designation (e.g.
"Superintendent of Police (SP) • District Headquarters, Warangal"
+ a stress-test user-typed name) or a long person-typed nickname.

## Fixes (3, all in `HomeScreen.kt`)

### P1-A — Subtitle `maxLines` + `overflow = TextOverflow.Ellipsis`

- `PersonRow` (line 711-781) — list-row subtitle gets
  `maxLines = 1, overflow = TextOverflow.Ellipsis`. List items should
  be 1 line; the row is a tap-target to the detail screen, and the
  existing row-level a11y label "Open person" already announces
  "more on tap".
- `HomeScreenSearchResults` person row (line 542-565) — search-result
  subtitle gets `maxLines = 2, overflow = TextOverflow.Ellipsis`. 2
  lines is enough context for a search result (a real station like
  "District Traffic Wing, Warangal" fits in 1 line) without letting a
  single bad row eat the viewport. The trailing `...` is a clear
  signal that more is on tap.

This single change addresses both issues 1 and 2:
- `maxLines` forces the line-break budget, so the
  `LineBreak.Heading`-style mid-word break can no longer fire (the
  "bile" half of `mobile` simply gets truncated by the ellipsis
  instead of being shown as a broken word).
- `overflow = Ellipsis` adds the `…` indicator that the old
  un-bounded Text was missing.

### P1-C — `contentPadding(bottom)` 88dp → 112dp (NoteBar clearance)

Both `PersonList` and `HomeScreenSearchResults` LazyColumns get
`bottom = 112.dp` (was `88.dp`). The NoteBar measures ~96dp
(Surface vertical padding 12dp + Row height 72dp + 12dp) and the
Scaffold's content `padding` should already include the bottomBar
height, but in practice the NoteBar's rounded-corner clip + the
FAB overhang left the last row half-hidden behind the bar on a
1080x2400 viewport. 112dp = 96dp NoteBar + 16dp visual buffer.

The NoteBar lives in the inner Scaffold's `bottomBar` slot (since
v1.6.3, when it moved out of a floating Box overlay — see the long
comment block at `HomeScreen.kt:202-212`). The padding values
themselves are unchanged in shape; only the magnitude is bumped.

## Out of scope (acknowledged, not fixed)

- **Build APK size grew**: 89.3 MB → 89.3 MB (no change; the
  `TextOverflow` import is compile-time only, the dp bump is a
  one-byte literal).
- **Search-results "Instructions" section** still uses unbounded
  Text for the person-header (line 593-607). v1.7.3 already added
  `heightIn(min = 32.dp)` to keep the bottom-of-viewport case from
  clipping to a few px. The header is `labelSmall` so the visual
  is already 1 line tall and adding `maxLines = 1` would be
  cosmetic only. Not fixed in v1.7.4.
- **A. Venkateshwarlu designation is still 80 chars long** in the
  fixture ("Sub-Inspector (Test — long designation used for layout
  edge cases)"). The original intent of this row was a layout
  stress test; the row is now bounded, so the stress is no longer
  visible at the row level. The fixture stays — the test data
  is useful for the per-person detail view's `Text` (which is not
  bounded). Not changed in v1.7.4.
