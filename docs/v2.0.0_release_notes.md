# Baton v2.0.0 — Local-only by design (drop Supabase)

**Release date:** 2026-08-24
**versionCode:** 42 (was 41)
**Branch:** `release/v2.0.0-supabase-drop`
**Tests:** 490 / 490 green (0 failures, 0 errors, 7 skipped — pre-existing skips; 7 test files deleted because they tested removed classes, 5 test files rewritten for the new local-only contracts)
**APK (debug, arm64-v8a):** TBD — drive-verify pending

> **v2.0.0 is a deliberate narrowing**, not a feature release. All
> Supabase cloud sync is removed. The app is now single-officer,
> single-device, local-only. This is the most privacy-respecting
> build of Baton to date; it is also the most narrow (no
> multi-device, no team, no shared state). The trade-off is
> documented in the README "What this is NOT" section and in
> the updated threat model.

> **⚠️ BREAKING CHANGE for pre-v8 users.** The v2-v7 destructive
> Room migration that was acceptable in v1.x (because Supabase
> would re-fill the local cache) is now a data-loss bug. Users
> upgrading from a pre-v8 build MUST back up via **Settings →
> Export (CSV/JSON)** before installing v2.0.0. The release
> notes call this out at the top.

---

## What changed

### Removed (the v1.x cloud)

- **Supabase** — all data/supabase/, data/sync/, data/auth/, ui/auth/ code is deleted. The schema still has the `sync_queue` table for forward-compat with an optional future cloud sync, but no code writes to it in v2.0.0.
- **Realtime sync** — `RealtimeSync`, `NetworkObserver`, `SyncEngine`, `CaptureSyncWorker`, `SyncDrainWorker`, `SupabaseEncryptedSessionManager` are all deleted. The `WorkManagerInitializer` keeps the same API but the three enqueue functions (`enqueueSyncDrain`, `enqueueCaptureSync`, `schedulePeriodicCaptureSync`) are no-op stubs.
- **Cloud auth** — `AuthRepository`, `AuthViewModel`, `AuthScreen`, `AuthUiState` are all deleted. v2.0 has no email/OTP sign-in; the device is the principal.
- **MCP cloud server** — gone. The in-app "check for updates" still hits the GitHub Releases API (no auth, no PII), but no other outbound call exists.
- **MindAnchor cross-app state** — `AppStateRepository.refreshFromNetwork` is a no-op. The local `app_state` table is in the schema for forward-compat but no code writes to it in v2.0.

### Added

- **Settings → Privacy → What's new** — the v1.9.11 `ChangelogScreen` is now reachable from Settings. The v1.6.0 design rule that forbids launch-time "What's new" modals is honoured. The Settings row is the canonical entry point; the screen reads `assets/changelog.json` and marks the current version as "seen" on dismiss.
- **v2.0.0 entry in `assets/changelog.json`** — the screen renders the v2.0.0 highlights at the top.

### Updated

- **README.md** — rewritten for the local-only scope. New "What this is NOT" section documents what was removed. The Stack section no longer mentions Supabase. The Privacy posture section now mentions ML Kit OCR as the one third-party SDK.
- **`docs/threat-model.md`** — rewritten for v2.0.0. The A4 (network eavesdropper) and A6 (cloud attacker) rows are now "vacuous by design" instead of "vacuous by vault-mode". A new A7 (Google Play Services for ML Kit OCR) is added; the user can disable OCR in Settings if A7 is in scope. A new §7 ("§8.2 — Third-party SDK surface") honestly documents ML Kit OCR, correcting the v1.x "no third-party AI" over-claim.
- **`SafeError`** — simplified. The v1.x HTTP-status-code mapper (RestException 401/403/422/429/5xx → specific user-facing strings) is gone. v2.0 only handles `IOException` (local disk / network) and a caller-supplied default. The leakage protection (BEAU-NEW-01: never include `e.message` in the user-facing string) is preserved.
- **`RoomPersonRepository` / `RoomInstructionRepository` / `RoomCaptureRepository` / `RoomTagRepository` / `AppStateRepository`** — `refreshFromNetwork(remote)` overloads removed. The `refreshFromNetwork()` no-arg version is a no-op in v2.0.0 but kept for the function contract.
- **`HomeViewModel.refreshTagsFromNetwork`** — called from `init` to preserve the v1.9.10 Obs-2 contract. The implementation is a no-op against the local Room cache; the user-facing error surface (a `HomeUiState.Error`) stays.
- **Build config** — `buildConfigField("SUPABASE_URL"/"SUPABASE_ANON_KEY")` removed. The `supabase-kt`, `ktor`, and `okhttp` deps are kept declared for transitive resolution (Glance needs okio 3.4.0 via the datastore Preferences dep, and the offline cache is missing okio directly).
- **`UpdateChecker`** — the only remaining network call. Provided with a real `HttpClient(OkHttp)` via `UpdateModule` (this was previously broken: the `HttpClient` had no provider, so a v1.9.x user who tapped "Check for updates" would have hit a Hilt `MissingBinding` error at runtime; v2.0 fixes it).

### Kept for forward-compat

- `sync_queue` Room table — schema v15 keeps it. A future v2.x that re-introduces optional cloud sync can write to it without a schema migration.
- `app_state` Room table — same. The MindAnchor cross-app state hibernate is in the schema but dormant.
- The `enqueueSyncDrain` / `enqueueCaptureSync` / `schedulePeriodicCaptureSync` API surface — kept as no-op stubs so a future v2.x can re-introduce the workers without a call-site refactor.

## Migration guide (for v1.x users)

### If you are on v1.8.0 or later (post-v8)

Your data is safe. The Room migration chain (MIGRATION_8_9 → MIGRATION_14_15) is preserved and the `vaultMode` column is still in the schema. v2.0.0 is a drop-in replacement.

After install:
1. Open the app. The Home screen is unchanged. Your people, instructions, captures, and tags are all there.
2. Settings → Privacy → What's new is the new entry point for release notes (replaces the launch-time modal that v1.6.0 had already removed).
3. Settings → Privacy → Threat model reflects the new local-only architecture. Read it.

### If you are on v1.7.x or earlier (pre-v8)

**⚠️ Your local DB WILL be wiped on the upgrade.** The v2-v7 destructive migration is in the Room fallback list. Before installing v2.0.0:

1. Open your current v1.7.x or earlier build.
2. Settings → Data → Export. Pick a SAF location. The CSV export is the safer choice (one row per person, instruction, capture, tag — text only, no photos).
3. Install v2.0.0.
4. v2.0.0 does not yet have a CSV/JSON import flow (the export was for your archive; the import is a v2.0.1 follow-up). If you need to re-create the data, type it back in by hand. (This is the honest answer for a pre-v8 user; a future v2.0.1 will add the import path.)

## What is NOT in v2.0.0

Documented in the README "What this is NOT" section. The short version:

- No multi-device sync.
- No cloud account / auth / email.
- No team / shared instructions.
- No analytics, no telemetry, no off-device crash reporting.
- No enterprise IT / MDM hooks.
- No third-party security audit (audit cost is out of scope for private R&D; the threat-model doc is the audit-ready state).
- No in-app audit-log viewer (the audit chain is written; the viewer is a v2.0.1 follow-up).
- No About page (the version is in the Settings sheet's existing row; a dedicated About screen is a v2.0.1 follow-up).

## Performance

- 490/490 unit tests pass.
- The build is smaller (no AAR for `BatonSupabase` wrapper, no Ktor client mock in test deps — though the runtime deps stay for the `UpdateChecker`).
- The Home screen is faster: no `realtime.changes` flow to collect, no per-write `enqueueCaptureSync` to fire, no `realtimeSync.start()` to register.

## Privacy

- All user data is on-device. SQLCipher-encrypted Room DB at `filesDir/databases/baton.db`. Keystore-backed `EncryptedSharedPreferences` for the passphrase.
- The only outbound network call is `https://api.github.com/repos/sampathmannam/baton/releases` (the in-app "check for updates"). No auth, no PII, no cookies.
- ML Kit OCR is the one third-party SDK that processes user content (photo captures). The user can disable OCR in Settings. The LLM and STT are on-device and do not call out.
- See `docs/threat-model.md` for the full threat model.

## Known gaps (deliberately deferred to v2.0.1+)

- In-app audit-log viewer — the chain is written; the viewer is a v2.0.1 follow-up.
- About page (dedicated screen) — the version is in the existing Settings row.
- CSV/JSON **import** (export exists; import is a v2.0.1 follow-up).
- Cryptographic vault mode (currently behavioural) — moves hidden rows to a second SQLCipher DB.
- Multi-user key sharing — the primitives exist; the cloud + team trust model is not built.
- Third-party security audit — out of scope for private R&D.
