## What's in the box

### Backup + restore (Phase 1 P0 #1)
Daily auto-backup to `filesDir/backups/` (7-day retention, plaintext JSON, SQLCipher at rest). One-shot "Back up now" in Settings. Round-trip restore covers 7 tables: persons, instructions, tags, captures, important dates, person links, instruction tags.

### Crash-recovery dedup (Phase 1 P0 #2)
A `lastSavedFingerprint` (text + mode + sortedTagIds hash) is written to `SavedStateHandle` BEFORE `clearDraft()`. On process-death + relaunch, a same-fingerprint save within the 30s window is detected and the duplicate is suppressed with an info message.

### Past-date Snackbar (Phase 1 P0 #4)
`CalendarGate.buildEventData` returns a sealed `CalendarEventResult` (`Event` / `Skipped(IN_PAST)`). The skip surfaces via a `SnackbarHost` in the capture sheet.

### Capture happy path instrumentation (Phase 1 P0 #7)
New `app/src/androidTest/.../CaptureHappyPathTest.kt` runs the full flow on an emulator. Plus the added `androidTest` deps unblock the pre-existing `M0AcceptanceTest` + `VaultEndToEndTest` compile errors.

### Vault recovery PDF (Phase 1 P1 #2)
Settings → Privacy → Recovery phrase → "Save as PDF" writes a paper-friendly A4 PDF of the 24-word seed to `cacheDir/recovery/`. Monospace font (BIP-39) so "sigh" / "high" don't look identical.

### Brief privacy gate (Phase 1 P1 #4)
`BriefGenerator.build` filters `is_sensitive = true` rows out of all 3 brief sections.

### Decay mark recent + undo (Phase 1 P1 #6)
"Mark as recent" TextButton in `DecaySection` pushes `UndoableAction.MarkPersonRecent`. Undo restores the prior `lastInteractionAt` (handles the null "never-touched" edge case).

### Audit chain (Phase 2 P0 #4)
SHA-256 hash chain on the `audit_chain_events` table. `AuditChainWriter` (anchored at `GENESIS_HASH` all-zeros sentinel) + `AuditChainVerifier` (returns `Intact(count)` / `BrokenAt(rowId, ...)`). Retention: 7 years (BNSS / IT Act), payload REDACTED on expiry, chain preserved.

### Retention (Phase 2 P0 #5)
`RetentionPolicy` + `RetentionWorker` (daily periodic via WorkManager). Captures 3y, dates 3y, instructions 7y, audit 7y. REDACT-not-DELETE on the audit chain so the hash chain's integrity value is preserved.

### Branding (Phase 2 P0 #6)
`BuildConfig.BRAND_NAME` / `BRAND_DEPARTMENT` / `BRAND_ICON` from `buildConfigField` in `app/build.gradle.kts`. Overridable via `gradle -Pbrand.name=... -Pbrand.dept=... -Pbrand.icon=...`. Default R&D build unchanged.

### eFIR bridge (Phase 2 P0 #7)
`CctnsBridge` interface (4 methods: push instruction closed, push FIR photo, register court date, push declassification). `NoOpCctnsBridge @Inject @Singleton` returns `NotConfigured` for every method (call sites fail LOUDLY — no fake "succeeds").

### Role model (Phase 2 P0 #3)
`UserEntity` + `Role` enum (ADMIN / SENIOR_OFFICER / OFFICER / READONLY, fallback to SENIOR_OFFICER on unknown) + `UserBootstrap.ensureDeviceOwner` (idempotent insert of the device-owner row). v14→v15 migration with partial unique index on `deviceOwner = 1`.

### Sync conflict UI (Phase 2 P0 #2)
Settings → "Sync conflicts" row (visible only when count > 0). `SyncConflictListScreen` (newest-first by `detectedAt`) + `SyncConflictDiffScreen` (side-by-side local vs server). The "Keep local" / "Keep server" buttons are placeholders for the future cloud-sync build (vault-mode has no cloud).

### Multi-user key sharing (Phase 2 P0 #1)
`MultiUserKeySharing` (pure-JVM, AES-256-GCM share + PBKDF2-at-600K-iter KEK). The class is built and tested; the wire-up to the actual SQLCipher key derivation is a v2.x change.

### Offline queue cap (Phase 2 P1 #4)
`SyncQueueDao.trimToLimit(maxSize)` + `SyncEngine.enqueueWithCap(entry)` + `SyncEngine.MAX_QUEUE_SIZE = 1000`. Oldest-wins eviction via `ORDER BY id DESC LIMIT -1 OFFSET N`.

### Photo stamp (Phase 2 P2 #3)
`PhotoStamp.stamp(context, uri, deviceOwnerDisplayName, caseId)` reads the JPEG from `cacheDir/captures/`, scales to max 2048px, draws a "BATON · {owner} · {iso ts} · case {caseId}" watermark in the bottom-right (white text on a semi-transparent black pill), and re-encodes at quality 92.

### Threat model document (Phase 3 P0 #1)
`docs/threat-model.md` (10.5 KB). 6 adversary classes (Forensics, Coercive, Shoulder-surfer, Network, Malicious app, Cloud), 9 assets, 7 defenses, 4 known gaps, 4 user responsibilities, v2.x roadmap.

### Privacy policy (Phase 3 P0 #2)
`docs/privacy-policy.md` (5.4 KB). "We do not collect any data" (v1.5.0+ is local-only). Rights surface (export / backup / erase / recovery / vault mode). Cloud-sync opt-in for the future v2.x.

### Android CI (Phase 3 P0 #8)
`.github/workflows/android-ci.yml` (3.4 KB). 3 jobs: `unit-test` (testDebugUnitTest on JDK 17 / Ubuntu with Gradle cache + test-results artifact), `lint` (Android lintDebug with report artifact), `assemble` (assembleDebug with APK artifact, depends on unit-test).

### Tamil + Hindi partial translations (Phase 3 P0 #3 partial)
`values-ta/strings.xml` (7 KB) + `values-hi/strings.xml` (6 KB). ~30 of the 354 strings translated. The remaining ~320 fall back to English.

## What's deferred (per persona)

Phase 2 P1 (most items), Phase 2 P2 (Tamil in brief / voice code-mix / officer offline), and Phase 3 (most items) are deferred because the persona is "no department support, private R&D, no deployment target". A future v2.x pilot with 2-5 officers in one station is the trigger for re-opening them.

The deferred items are catalogued in `docs/PRODUCTION_READINESS_PLAN.md` with the rationale for each deferral.
