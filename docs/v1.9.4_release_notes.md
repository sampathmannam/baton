## TL;DR

The v1.9.2 → v1.9.3 → v1.9.4 cycle chased "UI should use the screen
properly" through two layout flips of the DecayRow right-side
controls (vertical stack → horizontal siblings). v1.9.3 landed on
horizontal siblings with maxLines caps, but cards were still
~250px tall with too much vertical bloat around them. v1.9.4
closes the remaining gaps in one pass.

**Result:** 5 full DecayRow cards now visible on the Today screen
(1080×2400, 420dpi), up from 3 in v1.9.3 and 4 in the
v1.9.4-pre-polish pass. 8+ cards visible per scroll instead of 3-4.

## What changed

### 1. DecayRow card layout — proper compactness

- `heightIn(min = 88.dp) → 72.dp` — the 88dp floor was a v1.7.3
  anti-collapse guard. With the v1.9.2 `maxLines` caps the natural
  card height is already ~70dp. 72dp keeps the touch target
  comfortable without padding empty space.
- Inner `padding(vertical = 12.dp) → 10.dp` — 4dp saved per card.
- `Spacer(height = 2.dp) → 1.dp` between designation and days-quiet.

### 2. DecaySection — less inter-section bloat

- Outer `Column.padding(vertical = 8.dp) → 4.dp`.
- Inter-element `Arrangement.spacedBy(8.dp) → 6.dp`. Five gaps in
  the section header / subtitle / chips / banner / rows chain =
  10dp saved end-to-end.

### 3. Today's win card — no more 140px-tall card for two lines of text

- Inner `Column.padding(16.dp) → PaddingValues(horizontal = 16.dp,
  vertical = 12.dp)`.
- Outer `Card.padding(vertical = 8.dp) → 4.dp`.
- Internal `Arrangement.spacedBy(4.dp) → 2.dp`. Two text lines +
  24dp vertical padding is now ~70dp tall (down from ~94dp).

### 4. TodayScreen LazyColumn — tighter inter-item spacing

- `contentPadding(vertical = 8.dp) → 4.dp`.
- `verticalArrangement.spacedBy(8.dp) → 4.dp`. 4dp of vertical
  contentPadding + 4dp of inter-item spacing gives the surface
  room to breathe without wasting 1/4 of the screen on gaps.

## Lessons from the v1.9.2 → v1.9.4 cycle

The user feedback "UI should use the screen properly" landed
after v1.9.3 was already shipped. The natural fix was to
re-layout the cards, and I tried two things:

1. **v1.9.2 (vertical stack of right-side controls)** — gave
   the left text column the full available width, so the name
   could stay on one line. But the cards doubled in height
   (~292px → only 3 full + 1 partial visible).
2. **v1.9.4-pre-polish (horizontal siblings + maxLines caps)** —
   reverted to the v1.9.1 side-by-side layout, but bounded the
   left text to ≤4 lines (name 2 + designation 1 + days-quiet
   1, all ellipsized). Card height ~210px → 4 full + 1 partial.
3. **v1.9.4 final (this release)** — added the global padding
   pass on top: Today's win card 70dp (was 94dp), DecaySection
   inter-section gap 6dp (was 8dp), LazyColumn inter-item gap
   4dp (was 8dp). Card height stays ~210px but more cards
   fit per scroll, and the wasted space between sections is
   gone.

The lesson: **don't trade horizontal cramping for vertical
bloat**. Use `maxLines` caps as the constraint first, then
tune the global padding/section spacing. A 3-step polish cycle
when one would have been better, but the user-driven
verification caught both bugs (vertical stack of right-side
controls, then 4dp of remaining bloat) that the unit tests
and a11y audit missed.
