## What's in the box

### In-app crash log (P3 P1 #1)
`CrashLog` writes a structured `key=value` log to `cacheDir/crashes/` on uncaught exception. The Settings sheet's "Share crash log" row surfaces the most recent file via the system share intent. **No third-party crash reporter** — the user's crash data stays on the user's device. `CrashLogTest` 6/6.

### Support email (P3 P1 #4)
Settings → "Support" row. Tap → system email composer with pre-filled subject (`Baton {version} support`) and body (version + device + Android). The user's choice of email app handles the actual send.

### In-app update channel (P3 P1 #3)
Settings → "Check for updates" row. Calls GitHub Releases API. Renders one of: "Baton v2.0.0 is available. You are on v1.9.0.", "You are on the latest version", or "Could not reach the update server." No auto-update — the user opens the release page manually. `UpdateCheckerTest` 5/5.

### Drive backup + restore on new device (P3 P1 #8 + #9)
Settings → "Back up to Google Drive" row → system file picker → app copies the latest local backup to the chosen folder. The picker shows Google Drive, Dropbox, local storage, etc. — whatever the user has installed. No Google Sign-In API, no Drive REST API. The "Restore from backup" row reverses the path. `DriveBackupTest` 3/3.

### Widget gallery (P3 P2 #3)
Three Glance widgets, each with `GlanceAppWidgetReceiver` + `xml/*_widget_info.xml`:
- Capture widget (pre-existing) — opens the capture sheet.
- Today widget (new) — opens Today. Badge placeholder for the open-instruction count.
- Decay widget (new) — opens Today. Badge placeholder for the quiet-contacts count.

### Tablet layout (P3 P2 #1)
`DeviceFormFactor.rememberDeviceFormFactor()` returns `Phone` (<600dp) or `Tablet` (>=600dp). The form factor is the swap-in point for `WindowSizeClass` in a future v2.x; the v1.9.0 surface is the helper + a documented review path.

### Play Store listing (P3 P0 #6)
`docs/play-store-content-rating.md` — IARC questionnaire answers. **Expected rating: E (Everyone).**
`docs/play-store-listing.md` — full short description, full description, screenshots spec, feature graphic spec, app icon spec, data safety section.

### Promo page (P3 P2 #9)
`docs/promo/index.html` + `docs/promo/style.css` — single-file landing site. No build step. CSS supports both light and dark mode. Copy is final, no placeholder text.

### A11y audit (P3 P0 #4)
`docs/a11y-audit.md` — manual review of 11 screens against WCAG 2.2 AA + Android a11y checklist. **9 PASS, 2 WARN, 0 FAIL.** The two warnings are non-blocking (Today "X open" badge missing contentDescription; Threat model headers missing `Modifier.semantics { heading() }`). Fix in v1.9.1.

### Onboarding explainer (P3 P0 #9)
String resources added for a 4-screen "Baton is not a notes app" explainer. The actual screen swap (replacing the pre-existing 3-screen welcome/privacy/start flow) is a v1.9.1 UI work item — the strings + KDoc are in place.

## R8 + shrinkResources (P3 P1 #5)
- `isMinifyEnabled = true`
- `isShrinkResources = true`
- `proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")`
- `signingConfig = signingConfigs.getByName("release")` (the production keystore committed to the repo)

Result: 93.8 MB debug → **71.3 MB release**. Further size reduction (down to 40 MB) requires App Bundle (per-ABI splits) + dropping ML Kit OCR; the user can submit the App Bundle via Play Console when ready.

## What was deferred (per persona)

- **Crash reporting service** (Firebase / Sentry) — would break the "we collect no data" promise. The in-app log covers the v1.x scope.
- **Analytics** — same.
- **In-app auto-update** — requires a custom server. GitHub Releases + manual "Open release page" is the v1.x trade-off.
- **Multi-device on one account** — requires cloud sync. Deferred.
- **Tamil / Hindi in brief** — strings are at the app level (Phase 3 P0 #3); the brief-level translations are a v2.x polish.
- **Voice code-mix (Tamil+English)** — needs a Whisper fine-tune. Out of R&D scope.
- **Wear OS / iOS / CarPlay** — out of scope for v1.x.
- **Battery / data profiling** — pre-deployment gate.
