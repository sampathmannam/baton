### P0-A: Stale seeded data on upgrade

**Problem.** v1.7.2 changed the worry-box dates in
`assets/synthetic-data.json` (anchored at 2026-08-20 instead of
2026-08-15). But the Room DB on existing users' phones was never
re-seeded — the user kept seeing "Review in 3995" for worry rows
because the underlying `reviewAtEpochDay` value was still computed
from the v1.7.1 dates. The user had to manually go to Settings →
Developer → "Clear & reload" to pick up the new fixture.

**Fix.** Added a top-level `version: 2` field to the fixture JSON
(separate from the existing `schemaVersion: 2` which is data
structure metadata, not data content). Added
`FixtureLoader.reseedIfStale()` which:

1. Reads the asset's `version` at next launch.
2. Compares it against the value stored in SharedPreferences
   (key `fixture_version/version`, default 0).
3. If `stored < asset`, runs the full `loadFromAssets()` path.

`AppInitializer.runOnAppStart()` calls `reseedIfStale()` in a
background coroutine (`appScope.launch(Dispatchers.IO)`). The call
is **not** DEBUG-gated — for a private R&D single-user app, every
launch doing a one-shot version check is the right trade-off. The
clear+insert path is idempotent against an empty DB so cold-start
re-seed is a no-op except for the SharedPreferences write.

**Drive-verified.** Today worry box shows "Evening review /
2026-08-20" with realistic titles, not year 3995. The previous
v1.7.2 install was reseeded on first v1.7.3 launch.

### P1-C: Export CSV/JSON has no radio state

**Problem.** v1.7.0's St2 (deferred through v1.7.0, v1.7.1, v1.7.2):
the Settings → Data → "Export as CSV or JSON" section had two
side-by-side buttons with no visible radio/checkbox state. The user
couldn't tell which format was last used or which was default.

**Fix.** Replaced the two side-by-side buttons with two Rows, each
containing a `RadioButton(selected = …)` + `Text(label)`. The
selected format is held in a local `selectedPlainFormat` state
(default `"csv"`). Tapping a Row both sets the radio state AND
launches the export immediately — one-tap UX preserved.

**Drive-verified.** Settings → Data → Export as CSV or JSON shows
two distinct rows at `[63,634][529,760]` (CSV) and
`[550,634][1017,760]` (JSON), each with a radio button. App
version "1.7.3 (build 29)".

### P1-D: M3 NavigationBarItem `clickable=false` H3

**Problem.** v1.7.0's H3 (deferred): the active tab in the
Material 3 `NavigationBarItem` reports `clickable=false` in the
uiautomator dump because of the `selected=true` child state. The
Surface passes the click through, but the hierarchy reads as
"not clickable", which a) breaks automation scripts and b) is
inconsistent with the inactive tabs (which report
`clickable=true`).

**Fix.** Replaced the M3 `NavigationBarItem` with a custom
`Row(weight=1f)` containing `Modifier.clickable(onClick = onClick)`
on the Row itself. Visual selected indicator: `MaterialTheme.colorScheme.primary`
tint on the icon + label, plus a 3dp wide × 3dp tall `Box` with
`CircleShape` background below the label (mirrors M3's pill).

**Drive-verified.** All 3 bottom-nav tabs (Home, Today, Settings)
report `clickable=true` on the parent Row in the uiautomator dump
on both Home (`ui_v173_home.xml`) and Today (`ui_v173_today.xml`)
screens. Bounds: `[0,1896][346,2065]`, `[367,1905][713,2055]`,
`[734,1905][1080,2055]`, each 346×~150 dp.

### P2-A: Quiet-contacts row clipped

**Problem.** The v1.7.2 P2-B fix (last row of People list) added
`heightIn(min = 88.dp)` to `PersonRow` to prevent clipping at the
bottom of the Home tab. The same problem existed in
`DecayRow` (Today screen "Quiet a while" section) — when a
quiet-contact row had no subtitle or a long wrap, the row would
render at h<88dp and the last row would clip behind the
NoteBar.

**Fix.** Added `heightIn(min = 88.dp)` to the `DecayRow` Card
modifier, same pattern as v1.7.2 P2-B.

**Drive-verified.** Today worry box → "Quiet a while" → first
quiet contact (B. Ramesh Naidu) renders at bounds
`[84,1193][996,1424]` (h=231dp, well above 88dp minimum).

### P2-C: (unknown person) header clipped

**Problem.** In Today / Home search results, when an instruction's
`personId` points to a person NOT in the visible set (e.g.
sensitive person currently hidden), the group header reads
"(unknown person)" via `personNameById[personId] ?: "(unknown person)"`.
The header is a plain `Text` inside a `LazyColumn item` with
`padding(vertical = 4.dp)`. When the row landed at the very bottom
of the visible LazyColumn, the row was being clipped to a few
pixels (h=5 in the v1.7.2 dump), making the header nearly invisible.

**Fix.** Added `heightIn(min = 32.dp)` to the header Text
modifier, so the row always has a minimum visible height of 32dp
even at the LazyColumn bottom edge. This is a defensive minimum
that keeps the `labelSmall` glyphs legible regardless of
LazyColumn scroll position.

**Source-verified.** Code change in HomeScreen.kt:594-607. The
emulator search test didn't surface an actual hidden-person
result (the v1.7.3 fixture has all persons visible by default)
but the fix is in place for the edge case.

## Reusable patterns from this work

1. **Version-gated reseed for private R&D single-user apps.**
   The fix doesn't need a "is this a fresh install?" check or a
   destructive migration. It just compares an int in
   SharedPreferences against the same int in the asset. Cold-start
   reseed is a no-op for the data (clear+insert against empty
   DB). The cost is one SharedPreferences read + (usually) one
   asset parse on every launch; the benefit is "any fixture
   change deploys to existing users without manual
   intervention". For private R&D this is the right trade-off; for
   multi-user production this would need an opt-in flow.

2. **Radio+Row for one-tap exports.** The radio is a visible
   state indicator; the Row is the click target. Tapping the
   Row both sets the state and fires the action. This preserves
   the "one tap to do the thing" UX while making the
   which-format-is-current visible. A "Settings" page in the
   "low-arousal" product family should never require two taps
   (one to choose, one to confirm) — that adds friction to a
   task the user is doing reflexively.

3. **Custom Row replaces M3 NavigationBarItem when click-target
   semantics matter.** The M3 component is fine visually but
   its selected-state accessibility tree reports
   `clickable=false`, which is misleading for automation. A
   custom Row with the same visual chrome (icon + label +
   active-pill) is one screen of code and unblocks a11y
   tooling.

4. **`heightIn(min=…)` on row Cards** is the right answer for
   the "last row clipped" pattern. Don't use a Spacer, don't
   increase contentPadding (that pushes the whole list up
   instead of just the last row). A per-row minimum is
   local and predictable.

## What's still open

The 4-5/10 range of the v1.7.2 critique reflects deep product
gaps (no cloud sync, no real auth, no notifications, no widgets)
that are out of scope for the v1.7.x polish series. The next
round of work (v1.8.x or a feature-level reset) needs to
address those, not more P2 critique items.
