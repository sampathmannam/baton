# Baton v1.7.0 — fresh-eyes critique

**Base:** v1.7.0 (commit 556458f, tag v1.7.0) installed on ZD2232FCR5.
**Method:** Cold-walk every screen on the phone, dump UI hierarchy, score each
area on a 0-10 scale, list concrete issues with evidence. No source-code
review in this pass — this is the user-facing critique only.

**Scoring rubric (per area, 0-10):**
- 0-3: broken or unusable
- 4-5: works but with rough edges, missing affordances, or confusing
- 6-7: solid, minor polish needed
- 8-9: clean, only nitpicks
- 10: nothing to change

---

## Composite score: **3/10** — three P0 nav/UX bugs block core use

The v1.7.0 UI/UX overhaul from v1.6.8 fixed visual polish (typography,
spacing, dark-mode color tokens), but introduced or left in place three
navigation/UX bugs that make the app not work as a daily driver:

- The bottom-nav Home tab is `clickable=false` in the UI hierarchy AND
  the active-tab indicator lies about which tab is selected.
- Tapping Today or Settings in the bottom nav from the Home screen
  switches the user to a different foreground app (BSA for Dummies) —
  the system gesture-nav home/recents buttons are intercepting taps in
  the bottom-nav area, and the 48dp bottom-padding fix from v1.6.8 is
  not enough on the Home screen.
- The Today screen has Today/Review sub-tabs but no return path from
  Review back to Today.

Plus several P1 visual / data issues (placeholder data leaking into
the fresh-eyes walk, a duplicate person entry, the top search bar is a
non-functional placeholder, etc.).

## Area 2 — Home (People list) screen

**Score: 2/10.** The screen renders, but **the bottom-nav Today and
Settings tabs are not tappable** from here — tapping them switches the
user to a different foreground app instead of navigating. This is a
daily-driver blocker.

**Issues:**

| # | Severity | Issue | Evidence |
|---|---|---|---|
| H1 | **P0** | Tapping the Today tab in the bottom nav from the Home screen opens BSA for Dummies instead of navigating to Today | `adb shell input tap 632 2444` while on Home → `mCurrentFocus=com.bsa.dummies.debug/com.bsa.dummies.MainActivity` (confirmed via `dumpsys window`) |
| H2 | **P0** | Tapping the Settings tab in the bottom nav from the Home screen opens BSA for Dummies instead of opening Settings | Same as H1 with x=1061 |
| H3 | **P0** | The Home tab itself is `clickable=false` in the UI hierarchy | UI dump from `ui_today.xml` (when on Today) and `ui_h6.xml` (when on Home) both show the Home tab area at `[0,2324][406,2564]` with `clickable="false"`. The Today and Settings tabs at the same y-band are `clickable="true"` |
| H4 | P0 | The active-tab indicator is wrong: Home tab shows `selected="true"` while the user is on the Today screen, and vice versa | UI dump: Home tab is `selected="true"` on both Home and Today screens; Today and Settings are `selected="false"` even when active |
| H5 | P1 | The Home tab label is rendered but the parent clickable area is missing | Same node hierarchy as H3; nested children (text, icon) are all `clickable="false"` |
| H6 | P2 | No screen title — first text is "People" (top-left), then immediately person cards | "People" header at the very top is small and easy to miss |
| H7 | P2 | Same test-data placeholders as T4 show in the people list | UI dump shows "XXX...", "AAAA...", "Station-with-a-very-long-name-..." |
| H8 | P2 | Same B. Srinivas duplicate appears in the people list | UI dump shows two "B. Srinivas" entries with different roles |

**Root cause for H1 / H2 / H3 / H4:** the v1.6.8 fix added
`navigationBarsPadding() + padding(bottom = 48.dp)` to the bottom
`NavigationBar` in `MainActivity.kt` lines 503-510. On a 3-button
gesture device, the system home/recents/back hit areas sit at the
bottom of the screen. The 48dp (126px at 480dpi) bottom padding lifts
the nav bar above the system nav, but only just barely. The Home
screen has an inner `Scaffold` with its own `bottomBar` (the
`NoteBar` with capture buttons at y=2120-2288), and the outer
NavigationBar starts at y=2324. The combined height pushes the
center-bottom of the NavigationBar close to the system gesture-nav
home/recents buttons, and the system captures the taps.

**Drive-verified on ZD2232FCR5** (Android 17, 1264x2780, 3-button nav).
