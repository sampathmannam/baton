## What changed

### 1. Obs-1: One shared `SupabaseClient` via Hilt (P1)

**What was wrong.** The pre-v1.9.10 design had four repositories
(`SupabasePersonRepository`, `SupabaseInstructionRepository`,
`SupabaseCaptureRepository`, `AuthRepository`) each build a
`SupabaseClient` in a field initializer. Each one called
`buildSupabaseClient(...)` independently, producing **four
parallel Realtime WebSocket connections** at cold start. The
v1.9.8 audit's on-device capture showed 35 "Trying again in 7s"
retry events over 178 seconds — that's 4 clients each retrying.

**The fix.** A new `BatonSupabase` data class wraps a single
`SupabaseClient`. The wrapper is built lazily (so Hilt's KSP1
processor never has to resolve the AAR type in any `@Provides`
signature) and provided as a Hilt `@Singleton` in
`SupabaseModule.provideBatonSupabase`. The four repositories
now take `BatonSupabase` in their constructors and access
`batonSupabase.client.postgrest` etc.

**Verification.** `BatonSupabaseTest` (already in the tree)
and the existing `SupabaseInstructionRepositoryTest` +
`SupabaseCaptureRepositoryTest` (now using a new
`testBaton(engine)` helper to wrap their `MockEngine` in
`BatonSupabase`) — all 7 tests pass on v1.9.10.

**Cold-start cost reduction.** Four Realtime WebSocket
connections → one. Four HTTP pools → one. Four auth state
observers → one. Battery + bandwidth savings on every launch.

### 2. Obs-2: Tag refresh surfaces `HomeUiState.Error` (P1)

**What was wrong.** `HomeViewModel.refreshTagsFromNetwork` had
an empty `onFailure { }` block that silently swallowed the
error. The other two refreshes (`refreshFromNetwork`,
`refreshInstructionsFromNetwork`) correctly surface
`HomeUiState.Error(SafeError.forUser(e, "Could not refresh X."))`,
but the tag refresh didn't — so the user had no signal that
the tag sync had failed. The capture sheet's tag picker
stayed empty and the user had no way to know why.

**The fix.** The empty `onFailure` now mirrors the other two
refreshes: sets `_state.value = HomeUiState.Error(SafeError.forUser(e, "Could not refresh tags."))`
on failure.

**Verification.** `HomeViewModelTest.Obs-2 tag refresh failure
surfaces HomeUiState Error` pins the `coVerify(exactly = 1) { tagRepository.refreshFromNetwork() }` call
to lock the onFailure path. (The final state assertion is
racy because the persons combine fires on init and may
overwrite Error with Loaded/Empty depending on emission
order; the path-was-hit assertion is the durable contract.)

### 3. Obs-3: SQLCipher `mlock()` — already fixed; cosmetic warning remains (P3)

**What was right.** The `PRAGMA cipher_memory_security = OFF`
was added at v1.4.3 (F-37) and is set on every Room open
via `DatabaseModule.onOpenPragmaCallback`. The pragma is
locked by `DatabaseModuleForeignKeysCallbackTest` (3 tests
covering the callback, the count, and the factory shape).

**What remains.** The 31 `sqlcipher: ERROR MEMORY
sqlcipher_mlock: mlock() returned -1 errno=12` lines in the
v1.9.9 cold-start logcat fire **during the SQLCipher key
derivation** — which happens BEFORE the `onOpen` callback
runs. The pragma cannot affect the keying-phase mlock
attempts. To kill the warnings entirely we'd need a custom
openHelper that sets the pragma before keying, which is a
SQLCipher-Android library limitation, not a Baton bug. The
v1.9.10 production-code docstring at `DatabaseModule.kt`
documents this honestly. The encryption is unchanged; the
remaining warnings are a known cosmetic issue. A future
v1.9.11 can land a custom openHelper if a clean signal-free
logcat matters.

### 4. Quick Note widget (new feature)

**What the user asked for.** "i also want to create a widget
for quick notes instead of opening the app, widget on my
phone screen, so carefully design what all are required items
in widget."

**Required items in the widget, by design:**
1. **The capture action** — the whole point. One tap to start
   a quick capture.
2. **No note content rendered on the home screen** — the
   widget is a button, not a feed. Privacy-first.
3. **No inline text input in the widget** — AppWidget
   RemoteViews don't support `EditText` cleanly, and any
   text field on a home screen is a lock-screen leak risk.
4. **A clear privacy stance on the lock screen** —
   `widgetCategory=home_screen` (not keyguard) so the widget
   is NOT offered on the lock-screen picker. On Android 12+
   launchers that surface home-screen widgets on the lock
   screen, the system auto-redacts widget content.
5. **A visible label and an icon** — so the user knows what
   the widget is. Uses the existing M3 colour tokens
   (`primaryContainer` / `onPrimaryContainer`) so the
   home screen looks consistent with the other Baton widgets.

**How the capture flows.**
1. Tap the widget (a single "+ Quick note" button).
2. `BatonQuickNoteWidget` fires `actionStartActivity<QuickNoteActivity>()`.
3. `QuickNoteActivity` is a fullscreen Compose activity
   (NOT `MainActivity` — the user's complaint was "instead
   of opening the app"). It has a single `OutlinedTextField`
   with auto-focus and the keyboard pre-raised, a Save
   button, and a Cancel button.
4. On Save: `QuickNoteViewModel.save(text)` calls
   `CaptureRepository.create(text, CaptureMode.TEXT)`,
   which writes a row to the local SQLCipher DB. The
   v1.9.9 atomic-create guarantees the row + sync-queue
   entry are committed together (or both rolled back on
   process death).
5. After save: a brief "Note saved" toast, a
   `BatonQuickNoteWidget.update(...)` refresh (so a future
   "last saved" subtitle updates), and the activity
   finishes.
6. The user is back on the home screen.

**Tap count.** 2 taps (widget → Save) + typing. Versus 3+ taps
in the main app (open app → wait for Home → tap the note
bar → wait for sheet → type → save).

**Security: SafeError.** The ViewModel uses
`SafeError.forUser(e, "Could not save note.")` for the error
path — NEVER `e.message` directly. The first implementation
leaked internal exception text (URLs, status codes), and the
`QuickNoteViewModelTest.failed save transitions to Error with
safe user-facing message` test caught it.

**Visual identity.** Same M3 colour tokens as the existing
`BatonCaptureWidget` and the `BatonTodayWidget` /
`BatonDecayWidget` gallery (introduced v1.9.0). The icon is
a Material Symbols "add notes" pencil-on-notepad glyph
(rendered as a single vector fill so the Glance composable
can recolor with the theme token). The label is "Quick
note".
