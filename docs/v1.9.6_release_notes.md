## What changed

Three drive-verify polish fixes caught by real-device (and emulator) testing of v1.9.5. Each is a small but visible bug; together they bring the on-device rating from 8.0/10 (v1.9.5 fresh-rate) back to 8.5/10.

### 1. Snackbar no longer leaks UUID fragments (P0)
**Before (v1.9.5):** swiping right on a DecayRow showed `Mark recent 1a2b3c` — a slice of the action's UUID. The user saw an opaque hex token instead of a name.
**After (v1.9.6):** `Marked B. Ramesh Naidu as recent` — the person's name, exactly as expected.

The fix introduces a `displayName` field on the `UndoableAction` sealed interface, overridden per data class (`DeletePerson → name`, `DeleteInstruction → title`, `DeleteCapture → preview`, `MarkPersonRecent → name`). `MainActivity.kt:295` now reads `action.displayName` instead of `action.id.take(6)`. All four UndoableAction variants are covered.

### 2. Today's-win empty state points the user to Home (P2 copy bug)
**Before (v1.9.5):** `No captures today yet. Tap the note bar to start.` — but the note bar is on the PersonDetail screen, not the Today screen. Confusing on first run.
**After (v1.9.6):** `No captures today yet. Add one from the Home tab.` — accurate navigation.

The `person_detail_empty` string is deliberately left untouched (correct on PersonDetail).

### 3. DecayRow gesture hint (P1 discoverability)
Swipe-right and long-press to mark-recent were invisible affordances. v1.9.6 adds a one-time `AssistChip` above the filter row:
- Shows when `state.rows.size >= 3` AND `decay_gesture_hint_shown_v1 == false`
- Tap the chip to dismiss
- Also dismisses automatically after the first `markRecent()` (whether via swipe or long-press) — so users who already knew the gesture aren't pestered
- The new pref key is a boolean in `BatonPreferences` (DataStore), default `false` on fresh install
- Persists across sessions; no second showing
